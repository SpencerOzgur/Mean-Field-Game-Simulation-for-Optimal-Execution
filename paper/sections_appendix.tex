\section{Implementation notes}
\label{app:impl}

\paragraph{ABIDES.} We use \texttt{abides-core} and \texttt{abides-markets} from the \texttt{abides-jpmc-public} repository. Its order-size model depends on an old release of the \texttt{pomegranate} library that no longer installs; we substitute a small module that samples the same mixture distribution. The world builder mirrors the seeding order of the RMSC04 configuration and appends the execution agent last.

\paragraph{Stalls and runaways.} Each episode has a wall-clock limit and is retried once. \runawayText{}

\paragraph{DeepMarket.} The patch shipped with the code (i) removes non-blocking device transfers that corrupt integer tensors on Apple GPUs, (ii) restores the aggressor's fill notification for execution agents, (iii) shrinks a pre-allocated order-identifier pool, and (iv) allows loading our own checkpoint. The stock data builder splits by whole days and cannot process a one-day dataset; our training script splits the day chronologically instead. The simulation normalises inputs with whole-day statistics, whereas training used statistics of the first 85\% of the day; we did not correct this small mismatch.

\paragraph{A sign error in the pre-existing MFG solver.} The repository this study extends contains an iterative forward--backward solver for the MFG. With selling rate $\nu=-\dot q$, its backward step implements $\dot\nu = (2\phi q - A - \lambda\bar\nu)/(2a)$, whereas the Euler--Lagrange condition gives $\dot\nu = (A - \lambda\bar\nu - 2\phi q)/(2a)$: the inventory-penalty and drift terms have the wrong sign. Numerically, a more risk-averse seller trades \emph{later} under that solver and sells sooner when the price drifts up. We did not modify it; this paper uses the closed form of Section~\ref{sec:mfgmodel}.
